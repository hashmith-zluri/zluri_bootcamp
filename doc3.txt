DATABASE QUERY MANAGEMENT SYSTEM - PROJECT DOCUMENTATION
========================================================

PROJECT OVERVIEW
================
A comprehensive full-stack application for managing database queries and scripts with role-based access control, approval workflows, and secure execution environments. The system supports both PostgreSQL and MongoDB databases with advanced features like script execution in isolated worker threads and comprehensive audit logging.

API ENDPOINTS OVERVIEW
======================

Authentication APIs:
- POST /api/v1/auth/login - User authentication with JWT token generation
- POST /api/v1/auth/logout - Secure token invalidation

Request Management APIs:
- POST /api/v1/request - Submit database queries or scripts for approval
- GET /api/v1/request/mine - Retrieve user's submitted requests with pagination
- GET /api/v1/request/:req_id/result - Get execution results for specific requests

Approval Management APIs (Manager Only):
- GET /api/v1/approvals - List pending requests requiring approval
- POST /api/v1/approvals/:req_id/action - Approve/reject requests with automatic execution triggering

Database Configuration APIs:
- GET /api/v1/db/instances - List available database instances
- GET /api/v1/db/pods - Get POD configurations for database routing

SYSTEM WORKFLOW
===============

1. USER AUTHENTICATION
   - Users login with email/password credentials
   - JWT tokens generated with role-based claims (user/manager)
   - Tokens include user metadata and POD access permissions

2. REQUEST SUBMISSION
   - Users submit database queries (text) or scripts (.js files)
   - System validates request format and user permissions
   - File uploads processed and content stored securely in database
   - Requests enter "PENDING" status awaiting manager approval

3. APPROVAL WORKFLOW
   - Managers view pending requests with full context
   - Approval/rejection decisions logged with timestamps
   - Approved requests automatically trigger execution pipeline
   - Rejected requests notify users with reason codes

4. EXECUTION PIPELINE
   - PostgreSQL queries: Direct connection pooling with timeout controls
   - MongoDB queries: Shell command parsing with operation mapping
   - JavaScript scripts: Isolated worker thread execution with sandboxing
   - All executions logged with performance metrics and results

5. RESULT MANAGEMENT
   - Execution results stored with structured metadata
   - Users can view their request history and outcomes
   - Managers have visibility into all system activities
   - Comprehensive audit trail maintained

TECHNICAL CHALLENGES FACED
==========================

1. WORKER THREAD ISOLATION
   Challenge: Executing user JavaScript safely without compromising system security
   Solution: Implemented isolated worker threads with:
   - Temporary file management for script execution
   - Controlled global scope with limited API access
   - Automatic cleanup and resource management
   - Timeout mechanisms to prevent infinite loops

2. DATABASE CONNECTION POOLING
   Challenge: Managing multiple database connections efficiently across different engines
   Solution: Created engine-specific connection managers:
   - PostgreSQL: Connection pooling with automatic reconnection
   - MongoDB: Client caching with topology monitoring
   - Unified interface for both database types
   - Resource cleanup and monitoring capabilities

3. FILE UPLOAD SECURITY
   Challenge: Handling script file uploads securely
   Solution: Implemented comprehensive validation:
   - File type restrictions (.js only for scripts)
   - Content validation requiring console.log() for output capture
   - Size limitations and malware scanning considerations
   - Database storage instead of filesystem persistence

4. JWT TOKEN MANAGEMENT
   Challenge: Secure token handling with proper expiration and invalidation
   Solution: Built robust authentication system:
   - Active token tracking in memory
   - Automatic cleanup of expired tokens
   - Role-based access control integration
   - Secure logout with token blacklisting

5. TEST COVERAGE OPTIMIZATION
   Challenge: Achieving near 100% test coverage without ignoring critical code paths
   Solution: Comprehensive testing strategy:
   - Removed all Istanbul ignore comments
   - Created realistic test scenarios for edge cases
   - Mocked external dependencies effectively
   - Achieved 99.88% statement coverage with 307 passing tests
